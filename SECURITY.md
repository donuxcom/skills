# Security Policy

## Supported versions

Before a public release, only the latest v0.1.x release candidate is reviewed. Support is best effort with no response-time SLA.

## Report privately

Do not open a public issue containing secrets, personal data, exploit details, or a vulnerable repository. Use GitHub Private Vulnerability Reporting on the public repository. Publication is blocked until maintainers enable and test that channel. If it is unavailable, do not disclose details publicly; contact a monitored Donux maintainer through their GitHub profile and ask for a private channel without including the report.

## Scope

Reports may cover prompt injection, data exfiltration, excessive permissions, unsafe instructions, secret exposure, malicious references, archive traversal or symlinks, compromised dependencies or workflows, and tampered release artifacts. Maintainers will acknowledge when operationally possible, investigate, coordinate remediation and disclosure, and avoid promising a fixed timeline.

Never attach real credentials or customer data. Use synthetic reproduction material.
